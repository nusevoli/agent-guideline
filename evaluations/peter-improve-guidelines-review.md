# peter-improve-guidelines 작성 검사와 사례 적용

## 범위

스킬과 평가 참조 문서 작성, 형식·링크·범위 검사, 기존 도구 추천 사례에 대한 개선안 작성까지 수행했다. 공통 지침 수정·전역 설치·병합·새 독립 에이전트 실험은 수행하지 않았다.
원본은 이 저장소의 `skills/peter-improve-guidelines/`에서 직접 작성했으며 외부 스킬을 복사하지 않았다. 형식은 로컬 skill-creator 지침을 참고했다.

## 검사 결과

- skill-creator의 quick_validate.py: `Skill is valid!`.
- SKILL.md의 평가 참조 대상 존재 확인.
- 승인 범위, 부모 책임, 자기 검토와 독립 평가 구분을 내용 검토했다.
- 아래 적용은 작성한 SKILL.md를 명시적으로 읽고 같은 AI가 수행한 자기 검토다. 자동 선택·새 세션 로딩·독립 행동 준수·개선 효과를 입증하지 않는다.

## 사례 적용

| 구분 | 내용 |
| --- | --- |
| 목적 | 스킬 출처·업데이트·사용 이력·정리의 관리 부담을 줄일 방법 선택 |
| 관찰된 문제 | 수동 관리 구조를 먼저 제안하고 후속 질문마다 도구 후보를 추가. 비교 근거가 부족한 상태에서 조합 추천 |
| 기존 규칙 | integrations/README.md는 기존 자산 우선 조사, 호환성·유지보수·사용 경험 확인, 원본/수정/자체 작성/미설치 비교를 이미 요구 |
| 근거 원칙 | guidelines/evidence/sources.md는 자료 존재를 현재 적용 가능성으로 단정하지 않도록 요구 |
| 원인 판단 | 현재 후보 문서에 관련 규칙이 없었던 것은 아님. 해당 응답 당시 후보 문서 로딩 여부는 입증하지 못함. 관찰된 비교 부족과 문서 미로딩 원인 가설을 구분 |

## 개선 제안 — 미반영

1. integrations/README.md의 기존 선택 원칙을 구체화한다: 사용자 목적에 필요한 기능을 정리하고 기존 구성 유지·통합 도구·전문 도구 조합 중 유효한 대안을 비교한다. 고정된 후보 수는 요구하지 않는다.
2. 같은 문서에 추천 성립 기준을 추가한다: 핵심 요구 충족, 기존 환경 적합성, 유지보수와 사용 경험의 근거를 제시한다. 비교 근거가 부족하면 후보로 표시하고 미확인 항목을 밝힌다. 사용자 후속 질문을 기다리며 핵심 요구를 하나씩 누락하지 않는다.
3. guidelines/AGENTS.md의 도입 절차 읽기 조건을 실제 설치뿐 아니라 도구 추천·비교에도 명시적으로 연결하는 안을 검토한다. 당시 미로딩이 원인이었다고 단정하지 않는다.
4. 독립 평가에서는 자연스러운 관리 자동화 요청을 제공하고, 임의 수동 체계 작성이나 근거 없는 단일 추천으로 바로 진행하는지 관찰한다. 이 평가도 별도 계획 합의 후 수행한다.

공통 파일은 수정하지 않았다. 위 제안의 수정·실험은 다음 계획 합의 대상으로 남긴다. 도구 후보의 최신 기능을 재조사하는 작업은 이번 범위에 포함하지 않았다.
