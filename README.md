# Agent Guideline

시니어 개발자와 PM이 사용하는 AI 도구의 공통 작업 방식을 관리합니다.
[범용 지침](guidelines/AGENTS.md)은 목적 확인, 근거 판단, 계획·승인, 검증·보고 기준을 정의합니다.
프로젝트별 기술과 실행 절차는 각 프로젝트의 지침에서 관리합니다.

## 파일의 역할

| 파일 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 이 저장소를 개발·검증·운영하는 프로젝트 전용 지침 |
| [guidelines/AGENTS.md](guidelines/AGENTS.md) | 다른 프로젝트에서도 사용하는 범용 지침 원본 |
| `.github/ISSUE_TEMPLATE/` | 이 저장소의 개선·실험 기록 양식 |
| `.github/pull_request_template.md` | 변경 검토·승인 기록 양식 |

전역 설치 대상은 `guidelines/AGENTS.md`입니다. 루트 `AGENTS.md`를 전역으로 연결하지 않습니다.
프로젝트 배포 샘플, 지식 그래프, 평가 자료 디렉터리는 아직 구현하지 않았습니다.

## 변경 이력 관리

| 수단 | 기록할 내용 |
| --- | --- |
| Issue | 문제 사례, 개선 목적, 완료 조건, 실험 계획과 결과 |
| PR | 변경 이유, 변경 전후, 영향, 검증, 승인 상태 |
| 커밋 | 실제 파일 변경 이력 |
| 태그·Release | 실험으로 확인한 기준 버전과 알려진 한계. 필요할 때 별도로 생성 |

Issue에는 개선 제안과 지침 검증 실험 두 양식을 제공합니다.
PR 양식은 검토에 필요한 내용을 정리하는 도구이며, 승인이나 병합 제한을 자동으로 강제하지 않습니다.
이 구성은 브랜치 보호, Actions, 자동 병합을 활성화하지 않습니다.

## 작업 순서

1. 문제나 실험을 Issue에 기록합니다. 작은 변경은 PR에 목적과 근거를 직접 적어도 됩니다.
2. 변경 대상·영향·완료 조건을 정하고 필요한 승인을 받습니다.
3. 적용용 폴더가 아닌 별도 작업 폴더와 브랜치에서 수정합니다.
4. 변경 내용과 검증 결과를 확인하고 작업 브랜치를 업로드합니다.
5. `main`을 대상으로 PR을 열고 변경안과 미검증 사항을 검토합니다.
6. 병합 승인을 받은 뒤 병합합니다. 승인에 로컬 적용까지 포함되는지 명시합니다.
7. 로컬 적용도 승인됐다면 적용용 폴더가 깨끗한 `main` 상태인지 확인하고 `git pull --ff-only`로 갱신합니다. 기존 루트 원본에서 처음 전환하는 경우에는 아래 전환 절차를 먼저 따릅니다.
8. 원격 커밋과 적용 파일을 확인하고, 지침을 읽는 도구의 새 세션에서 적용 상태를 확인합니다.

PR을 병합해도 로컬 파일이 자동 갱신되지는 않습니다.
이전 작업의 승인을 새로운 변경이나 병합의 승인으로 간주하지 않습니다.

## 적용 후 로컬 구성

아래 경로는 현재 운영자의 환경이며 팀원별로 달라질 수 있습니다.

| 역할 | 경로 |
| --- | --- |
| 적용용 저장소 (`main`) | `/home/nusevoli/projects/agent-guideline` |
| 실험·수정용 Git worktree | `/home/nusevoli/projects/agent-guideline-work` |
| Codex 지침 연결 | `/home/nusevoli/.codex/AGENTS.md` → 적용용 저장소의 `guidelines/AGENTS.md` |

위 연결은 병합·로컬 반영과 링크 전환까지 승인받아 수행한 후의 구성입니다. PR 작성만으로 기존 링크가 바뀌지는 않습니다.

## 설치와 기존 경로 전환

새 환경에서는 저장소를 준비한 뒤 범용 원본을 읽고, 해당 도구가 읽는 개인 지침 경로에 `guidelines/AGENTS.md`를 연결하거나 복사합니다.
기존 개인 지침이 있으면 덮어쓰지 말고 내용을 검토하여 통합 범위를 승인받습니다. 루트 운영 지침은 배포하지 않습니다.
개인 경로는 사용자마다 달라지므로 위 표를 그대로 복사하지 않습니다.

기존에 전역 지침을 적용용 저장소의 루트 `AGENTS.md`에 연결했다면 다음 순서로 전환합니다.

1. 병합·로컬 반영·링크 전환 승인을 확인하고, 기존 링크 대상·적용 커밋·지침 내용을 기록합니다.
2. 적용용 폴더 밖에 기존 범용 지침의 임시 사본을 보관하고, 내용을 검증한 뒤 전역 링크를 임시 사본으로 원자적으로 교체합니다.
3. 승인한 PR을 병합하고 적용용 `main`을 fast-forward로 갱신합니다. 이미 원격에서 병합했다면 로컬 갱신만 수행합니다.
4. 새 `guidelines/AGENTS.md`가 이전 범용 지침과 바이트 단위로 같은지 확인합니다. 불일치하면 진행을 멈추고 임시 사본 연결을 유지합니다.
5. 전역 링크를 적용용 `guidelines/AGENTS.md`로 원자적으로 교체하고 원격·로컬 커밋, 대상 파일, 지침 내용이 일치하는지 확인합니다.
6. 새 세션에서 로드한 파일을 확인합니다. 확인 전에는 새 세션 적용까지 검증했다고 보고하지 않습니다.

임시 사본 연결은 로컬 갱신 중 루트의 프로젝트 운영 규칙이 전역 지침으로 읽히는 것을 막기 위한 절차입니다.
전환 실패 시 검증된 범용 지침 사본 연결을 유지하고 원인을 보고합니다. 전역 경로를 일반 파일로 사용하는 환경은 링크 전환 대신 승인된 설치 방식을 따릅니다.

적용용 폴더에서 실험 브랜치로 전환하거나 지침을 직접 수정하면, 링크로 읽는 내용도 바뀝니다.
실험은 별도 작업 폴더에서 수행하고 적용용 폴더는 승인된 버전으로 유지합니다.
다음 작업을 시작할 때는 이전 작업의 미커밋 변경과 PR 상태를 확인한 뒤 최신 `main`을 기준으로 새 브랜치를 준비합니다.
미완료 작업을 덮어쓰거나 강제로 초기화하지 않습니다.

실험 폴더의 지침을 수정해도 적용용 폴더를 가리키는 전역 Codex 링크는 바뀌지 않습니다.
실험 시에는 사용한 지침 버전과 도구가 실제로 읽은 지침을 확인하여 기록합니다.

## 사용자 행동 표시

| 표시 | 사용자 행동 |
| --- | --- |
| ⚙️ 자동 진행 | 응답 불필요. 승인된 범위에서 진행 |
| ✅ 승인 필요 | 계획·변경안을 확인하고 승인 또는 수정 요청 |
| 🧭 선택 필요 | 장단점·영향을 비교하고 옵션 선택 |
| 🙋 직접 작업 필요 | 안내된 위치에서 작업하고 완료 여부 전달 |

## 검증과 복구

- 문서 검증: 변경 차이, 링크, 양식, 불필요한 파일 포함 여부를 확인합니다.
- 행동 검증: 목적 이탈, 정보 부족, 승인 대기 등 시나리오별로 기대 행동과 관찰 결과를 비교합니다.
- 과제 성공 여부와 지침 준수 여부는 별도로 평가합니다. 아직 수행하지 않은 실험은 미실행으로 기록합니다.
- 병합 전: PR을 닫으면 `main`은 변경되지 않습니다. 작업 브랜치는 보존할 수 있습니다.
- 병합 후: 영향을 검토하고 승인받은 뒤 되돌림 커밋을 PR로 반영합니다. 로컬 적용본도 별도로 갱신합니다.
- 이번 경로 분리를 되돌리는 경우: 먼저 검증된 범용 지침 사본으로 전역 링크를 보호하고, 되돌림 커밋을 로컬에 적용한 뒤 루트 `AGENTS.md`가 이전 범용 지침으로 복원됐는지 확인합니다. 그 후 기존 루트 경로로 링크를 되돌리고 내용과 대상을 검증합니다.
- 공유 이력을 강제로 덮어쓰지 않습니다.

## 접근과 공개 범위

Git SSH 인증은 업로드에 사용합니다. Issues 설정 변경이나 PR 생성에는 별도로 GitHub 웹 로그인 또는 API 인증이 필요합니다.
인증이 없는 경우 브랜치 업로드 후 웹에서 PR을 생성할 수 있습니다.
Issue·PR·파일의 내용은 저장소 접근 범위에 따라 공유됩니다. 인증키, 계정 비밀 정보, 비공개 대화 원문은 기록하지 않습니다.
