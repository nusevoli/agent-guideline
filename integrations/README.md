# 역량 점검과 자원 보완

## 목표에 필요한 역량 점검

- 계획 수립 시 목표·완료 조건에 필요한 역량과 현재 자원을 대조한다. 자원에는 기본 기능, 스킬, 에이전트, 도구, 자료, 접근 권한을 포함한다.
- 새 목표, 중요한 범위 변경, 기존 방법의 한계가 드러났을 때 다시 점검한다. 매 요청마다 전체 설치 목록을 조사하지 않는다.
- 현재 제공된 기능 설명과 기존 검증 근거를 먼저 활용하고 관련 후보만 확인한다. 이미 확인한 내용은 변경 근거 없이 반복 조사하지 않는다.
- 설치·등록 여부, 현재 호출 가능 여부, 해당 과제에 대한 적합성을 구분한다. 설명이나 이름만으로 검증된 역량으로 판단하지 않는다.
- 불확실한 호출·접근 가능성은 승인된 범위에서 영향이 작은 확인으로 점검한다. 접근 권한 확인을 권한 확대 승인으로 해석하지 않는다.
- 충분하면 기존 자원으로 진행한다. 부족하거나 확인되지 않은 역량은 목표에 미치는 영향과 함께 명시한다.
- 기존 기능 조합, 직접 수행, 외부 도입, 합의된 범위 축소를 비교한다. 설치를 기본 해법으로 삼지 않는다.

## 부족한 역량의 보완

- 외부 보완이 유효하면 조사할 질문·범위·결과물·영향을 제안하고 기존 승인 범위에서 조사한다. 이미 승인된 조사는 반복 승인받지 않는다.
- 조사 결과에는 필요한 역량과 후보의 대응 관계, 추천 이유, 장단점, 유지보수·사용 경험 근거, 호환성, 권한, 비용, 적용 범위와 제거·복구 방법을 제시한다. 미확인 정보는 미확인으로 남긴다.
- 자료 확보·접근 연결도 같은 판단 기준을 적용한다. 비공개 자료 전송이나 권한 확대를 조사 요청만으로 수행하지 않는다.
- 도입이 필요한 작업만 응답 대기 또는 차단으로 관리하고, 승인된 독립 작업은 계속한다. 보완 없이 가능한 대안을 진행할 때는 결과 한계를 밝힌다.
- 설치·연결 후 실제 과제를 대표하는 작은 검증으로 호출·권한·출력·완료 조건 충족을 확인한다. 설치 성공과 과제 수행 가능을 구분한다.
- 검증이 실패하면 원인·대체 방법·복구 여부를 기록하고 해당 자원에 의존하는 작업의 재개 조건을 갱신한다. 성공하면 연결된 TODO를 승인 범위 안에서 재개한다.
- 중요한 점검 결과는 프로젝트의 관련 작업에 필요한 역량·선택 자원·미확인 사항·근거로 기록한다. 사소한 작업에 별도 문서를 강제하지 않는다.

## 도입 후보 선택 원칙

- 기본 도구와 설치된 스킬·에이전트로 가능한지 먼저 확인한다. 기술 이름만으로 설치를 요구하지 않는다.
- 부족한 기능과 도입 실익을 설명하고 기존 자산 재사용을 우선 조사한다. 직접 작성은 빈 부분에 한정한다.
- 후보의 실제 내용·호환성·지원 버전·권한·의존성·라이선스·유지보수·사용 경험을 확인한다. 스타 수와 홍보 문구를 품질 증거로 간주하지 않는다.
- 공통 승인·완료 기준과 충돌하는 절차, 무조건 질문·위임·반복하는 규칙을 확인한다.
- 원본 사용 / 필요한 수정 / 참고 후 자체 작성 / 설치 없이 진행을 비교한다.
- [도입 기록](adoption-record.md)에 변경안·경로·설정·영향·복구를 구체화한 후 설치 승인을 받는다. 기존 승인 범위면 재요청하지 않는다.

## 연결과 수명주기

- 필요한 기능과 결과 형식을 먼저 정의한다. 특정 도구의 명령을 공통 지침에 고정하지 않는다.
- 후보 보관·설치·활성화는 구분한다. 프로젝트 단위 적용을 우선 검토하고 전역 영향은 명시한다.
- 원본 출처·커밋/버전·라이선스 고지·로컬 변경 차이를 보존한다.
- 상태 원본과 작성 책임을 하나로 정한다. 어댑터는 원래 상태를 공통 상태에 매핑하고 불가능한 매핑은 알린다.
- 문서상 권고와 코드로 강제되는 기능을 구분한다. 지원하지 않는 기능은 대체·축소·차단 중 어떻게 처리할지 정한다.
- 설치 후 실제 호출·권한·필수 의존성·출력·중단·검증 동작을 확인한다. 목록에 표시된 것만으로 설치 검증을 완료하지 않는다.
- 업데이트는 버전과 차이·충돌을 검토한 뒤 승인 범위에서 반영한다. 자동 덮어쓰지 않는다.
- 제거·교체 전 작업을 안전하게 멈추고 공통 결정·상태·근거를 보존한다. 기록을 새 도구와 실제 코드에 대조하여 재개한다.
- 사용자 인증이 필요한 단계만 직접 작업으로 안내한다.

## 현재 범위

특정 프레임워크의 표준 채택·외부 스킬 설치·자동 실행기는 아직 구현하지 않는다.
Java·Spring·DB·JPA·MyBatis 등은 프로젝트 필요 시 조사한다. 기술별 프로필 묶음을 일괄 작성하지 않는다.
