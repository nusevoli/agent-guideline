# 전문 기능과 도구 도입

## 선택 원칙

- 기본 도구와 설치된 스킬·에이전트로 가능한지 먼저 확인한다. 기술 이름만으로 설치를 요구하지 않는다.
- 부족한 기능과 도입 실익을 설명하고 기존 자산 재사용을 우선 조사한다. 직접 작성은 빈 부분에 한정한다.
- 후보의 실제 내용·호환성·지원 버전·권한·의존성·라이선스·유지보수·사용 경험을 확인한다. 스타 수와 홍보 문구를 품질 증거로 간주하지 않는다.
- 공통 승인·완료 기준과 충돌하는 절차, 무조건 질문·위임·반복하는 규칙을 확인한다.
- 원본 사용 / 필요한 수정 / 참고 후 자체 작성 / 설치 없이 진행을 비교한다.
- [도입 기록](adoption-record.md)에 변경안·경로·설정·영향·복구를 구체화한 후 설치 승인을 받는다. 기존 승인 범위면 재요청하지 않는다.

## 연결과 수명주기

- 필요한 기능과 결과 형식을 먼저 정의한다. 특정 도구의 명령을 공통 지침에 고정하지 않는다.
- 후보 보관·설치·활성화는 구분한다. 프로젝트 단위 적용을 우선 검토하고 전역 영향은 명시한다.
- 원본 출처·커밋/버전·라이선스 고지·로컬 변경 차이를 보존한다.
- 상태 원본과 작성 책임을 하나로 정한다. 어댑터는 원래 상태를 공통 상태에 매핑하고 불가능한 매핑은 알린다.
- 문서상 권고와 코드로 강제되는 기능을 구분한다. 지원하지 않는 기능은 대체·축소·차단 중 어떻게 처리할지 정한다.
- 설치 후 실제 호출·권한·필수 의존성·출력·중단·검증 동작을 확인한다. 목록에 표시된 것만으로 설치 검증을 완료하지 않는다.
- 업데이트는 버전과 차이·충돌을 검토한 뒤 승인 범위에서 반영한다. 자동 덮어쓰지 않는다.
- 제거·교체 전 작업을 안전하게 멈추고 공통 결정·상태·근거를 보존한다. 기록을 새 도구와 실제 코드에 대조하여 재개한다.
- 사용자 인증이 필요한 단계만 직접 작업으로 안내한다.

## 현재 범위

특정 프레임워크의 표준 채택·외부 스킬 설치·자동 실행기는 아직 구현하지 않는다.
Java·Spring·DB·JPA·MyBatis 등은 프로젝트 필요 시 조사한다. 기술별 프로필 묶음을 일괄 작성하지 않는다.
