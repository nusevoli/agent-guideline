# 프로젝트 목표와 작업 연결

- 장기 프로젝트는 목적·대상 사용자·해결할 문제·성공 기준·제외 범위의 원본을 프로젝트에 지정한다.
- 특정 파일명이나 도구를 강제하지 않는다. 기존 제품 문서·이슈가 원본이면 링크로 재사용한다.
- 프로젝트 지침에 목표 원본과 TODO 원본, 읽는 조건을 명시한다. 두 문서에 같은 상태를 중복 관리하지 않는다.
- 목표 정의·변경, 새 단계 계획, 재개, 설계·리뷰 시 목표 원본과 관련 작업을 확인한다.
- 장기 목적 → 이번 단계 목표 → 작업 → 검증 근거로 연결한다. 단계 목표에는 식별자와 관측 가능한 성공 기준을 둔다.
- 장기 비전·현재 구현·미구현 제안·승인된 실행 범위를 구분한다. 비전 채택을 모든 기능의 실행 승인으로 해석하지 않는다.
- 작업에는 상위 목표 링크·기여 이유·완료 조건을 남긴다. 조사·유지보수·장애 복구도 목표 달성을 지원하는 이유로 연결할 수 있다.
- 사소한 작업마다 별도 목표 문서를 만들지 않는다. 작은 일은 기존 목표 참조와 짧은 목록으로 충분하다.
- 새 요청이 기존 목표와 충돌하면 [목적 확인](clarification.md)에 따라 차이와 영향을 설명한다. 방법 변경을 목표 이탈로 단정하지 않는다.
- 목표 변경 시 결정 이유와 영향을 기록하고 관련 작업을 유지·수정·보류·취소로 검토한다. 보류 항목의 실제 상태는 응답 대기 또는 차단과 사유로 표현한다.
- 작업 완료와 목표 달성을 구분한다. 산출물 제작만으로 사용성·품질·효율 향상을 입증했다고 보고하지 않는다.
- 목표 달성은 성공 기준의 근거로 판단하며, 부족하면 미달성 또는 미검증으로 남긴다.

실제 작업 상태와 승인 범위는 [상태 관리](../orchestration/state.md)를 따른다.
