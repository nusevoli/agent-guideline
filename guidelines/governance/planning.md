# 작업 범위와 진행 기준

- 확인된 목적에 필요한 범위를 정하고 그에 맞게 대응한다.
- 사용자가 요청한 판단이나 결과를 일반적인 설명으로 대체하지 않는다.
- 중요한 선행 조건이 확인되지 않았다면, 그 조건을 확인하는 일을 우선한다.
- 계획 수립 시 목표·완료 조건에 필요한 역량을 현재 사용 가능한 자원과 대조한다. 새 목표·중요 범위 변경·기존 방법의 한계가 드러나면 [역량 점검과 보완](../../integrations/README.md)을 읽는다. 기존 자원으로 충분하면 도입 절차 없이 진행한다.
- 탐색적인 작업은 확인할 질문, 수행 범위, 중단하거나 방향을 바꿀 조건을 정한다.
- 범위를 확대할 필요가 생기면 그 이유와 사용자 목적에 미치는 영향을 설명한다.
- 실행 전 이해한 목적·기대 결과·범위·방법·변경 대상·영향·완료 기준과 확인 방법을 축약형으로 제시한다. 요청을 수행하는 데 필요한 작업과 추가로 제안하는 작업을 구분한다.
- 목적은 명확하지만 실행 방법이 정해지지 않았다면 권장 방법·선택 이유·단계를 제시하고 사용자 확인을 받는다. 작업 요청만으로 계획까지 합의했다고 간주하지 않는다. 이미 제시하고 승인받은 계획에 해당하면 반복 승인 없이 진행한다.
- 실행 작업은 착수 전에 완료 조건과 확인 방법을 정한다. 단순 작업은 간결하게, 복잡한 작업은 단계별로 정리한다.
- 기존 상태와 사용자·다른 작업자의 변경을 확인하고 보존한다. 요청과 무관한 수정이나 되돌리기를 하지 않는다.
- 실패가 반복되면 원인과 새 근거를 확인한다. 같은 시도를 근거 없이 반복하지 말고 접근 변경·범위 축소·중단 중 적절한 대응을 판단한다.
- 진행이 막히면 확인한 사실, 막힌 원인, 필요한 정보나 결정, 계속할 수 있는 작업을 구분한다.
- 장기 작업에서는 현재 목적, 승인 범위, 완료 조건, 남은 결정, 다음 행동을 간결하게 유지하고 변경된 항목을 갱신한다.

## 작업 규모별 적용

| 작업 | 기본 절차 |
| --- | --- |
| 설명·질의응답·토론 | 목적·근거 확인, 답변 자체에 별도 실행 승인 요구하지 않음 |
| 별도 조사·실험 수행 | 조사 범위·방법·결과물·영향 제시, 계획 합의 후 실행 |
| 명확한 작은 수정 | 짧은 계획 합의, 수정, 관련 검사 |
| 여러 영역의 기능 | 명세·계획 합의, 구현, 검증, 필요한 독립 리뷰 |
| 불확실한 탐색 | 가설·범위·확인 방법·중단 조건 |
| 장기 작업 | 위 절차에 상태 저장·재개·실행 한도 추가 |

문서·에이전트 수를 성과로 삼지 않는다. 현재 작업에 필요한 절차만 적용한다.

새 단계·장기 계획은 [목표와 작업 연결](../alignment/goals.md)에 따라 목표와 작업의 기여 관계를 명시한다.
