# TODO와 작업 상태

## 원본과 책임

- 실제 TODO는 해당 프로젝트에 둔다. 총괄이 관리하며 하위 에이전트는 결과·근거·차단 사유를 보고한다.
- 프로젝트에서 상태 원본의 경로 또는 외부 시스템을 하나로 지정한다. 앱 목록·문서·이슈는 보조 표시일 수 있으나 독립된 원본으로 두지 않는다.
- 초기에는 Markdown [작업 양식](../../contracts/task.md)을 사용할 수 있다. 작은 작업은 대화 내 짧은 목록으로 충분하며 장기·위임·재개 작업은 지속 기록을 사용한다.
- 기록에는 식별자·목적·범위·담당·선행 조건·승인 범위·완료 조건·검증 근거·다음 행동을 남긴다. 불필요한 민감 정보와 대화 원문은 저장하지 않는다.

## 상태 전환

| 상태 | 진입 조건 | 나갈 조건 |
| --- | --- | --- |
| 대기 | 아직 시작하지 않음 | 선행 조건과 승인 범위 충족 시 진행 중 |
| 진행 중 | 담당자가 작업 수행 | 결과 준비 시 검증 중, 장애 시 차단/응답 대기 |
| 검증 중 | 완료 조건을 실제 결과와 대조 | 충족 시 완료, 결함이면 진행 중 |
| 사용자 응답 대기 | 선택·승인·직접 작업 필요 | 실제 응답을 기록하고 영향 검토 후 이전 단계로 복귀 |
| 차단 | 환경·의존성 등으로 진행 불가 | 해소 근거 확인 후 재개 |
| 완료 | 해당 항목의 완료 조건과 근거 확인 | 새 변경·반증으로 조건이 깨지면 이유를 남겨 재개 |
| 취소 | 명시적 취소 또는 승인된 범위 제외 | 재개 요청 시 범위·승인을 재평가 |

- PR 작성과 병합·반영처럼 완료 조건·승인이 다른 작업은 분리한다.
- 도구 호출마다 기록하지 않고 착수·결정·실패·검증·완료 등 의미 있는 변화 때 갱신한다.
- 미완료 항목이 있다는 이유만으로 실행하지 않는다. 독립성·승인·선행 조건을 확인한다.
- 한도 도달·차단·취소를 완료로 바꾸지 않는다. 전체 완료는 필수 항목의 결과와 제외 사유를 확인한 뒤 판단한다.
- 문서 상태는 실행 잠금이 아니다. 자동화 도입 시 저장·동시성·승인 대기 차단을 실제 실행기로 검증한다.

## 목표와의 연결

- 새 단계·장기 작업을 계획할 때 [목표와 작업 연결](../alignment/goals.md)을 읽는다.
- TODO는 상위 목표의 식별자·링크와 기여 이유를 가진다. 목표의 정의는 목표 원본을 참조한다.
- 착수·재개 시 목표·우선순위·승인의 유효성을 확인한다. 목표 변경으로 불필요해진 작업을 관성적으로 실행하지 않는다.
- 목표 변경의 영향 검토와 작업별 처리 이유를 기록한다. 이전 완료 근거는 삭제하지 않는다.
- 필수 TODO가 완료됐어도 목표 성공 기준의 근거가 없으면 목표 달성을 선언하지 않는다.
