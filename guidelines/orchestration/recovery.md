# 실패·중단·재개

- 장기 실행 전에 측정 가능한 반복·시간·사용량 한도와 진행 없음의 판단 기준을 프로젝트별로 정한다. 미측정 토큰을 임의로 추산해 한도로 보고하지 않는다.
- 동일 실패를 새 근거 없이 재시도하지 않는다. 환경 문제·구현 결함·요구 모순을 구분하고 원인 분석·접근 변경·범위 축소·중단을 판단한다.
- 사용자 응답 대기 중 해당 응답에 의존하는 작업은 재개하지 않는다. 시간 경과나 알림 수신을 승인으로 취급하지 않는다.
- 중단 요청을 받으면 모든 자동 재개 경로에서 확인할 중단 상태를 기록한다. 실행 중인 작업의 중지 가능 여부와 남은 영향을 확인한다.
- 이벤트 중복 수신으로 작업을 중복 실행하지 않도록 작업 ID·실행 ID와 실제 실행 상태를 확인한다.
- 재개 시 목적·결정 이유·승인·선행 작업·변경 파일·커밋·환경·검증 근거를 실제 상태와 대조한다. 기록만 믿고 완료 작업을 반복하거나 미검증 결과를 재사용하지 않는다.
- 관련 코드·환경이 바뀌면 검증 근거의 유효성을 재평가한다.
- 도구 교체로 세션 자체를 이전할 수 없다면 그 한계를 알리고 공통 기록에서 재개한다.
- 자동 실행기의 모든 재개 경로가 같은 중단·승인·한도를 확인하는지는 통합 시험으로 확인한다. Markdown 작성만으로 구현됐다고 보고하지 않는다.
