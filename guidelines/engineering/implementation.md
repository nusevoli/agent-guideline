# 구현 공통 기준

- 수정 전에 프로젝트 지침·관련 코드·버전·빌드 및 검사 설정을 확인한다.
- 요구를 충족하는 최소 범위로 변경한다. 관련 없는 리팩터링·의존성·추상화를 추가하지 않는다.
- 기존 계약·공개 인터페이스·데이터 호환성을 확인한다. 변경이 필요하면 영향·이전·복구 방법을 설명한다.
- 이름은 역할과 도메인 용어를 드러내고 기존 용어와 일관되게 정한다. 언어별 표기법은 프로젝트 규칙을 따른다.
- 포맷·린트 설정은 해당 설정 파일을 원본으로 삼는다. 문서에 동일 규칙을 중복 나열하지 않는다.
- 오류 처리·자원 관리·동시성·보안 등은 실제 변경의 위험에 맞춰 검토한다.
- 언어·프레임워크·DB·실행 명령은 프로젝트에 기록한다. 전문 기능이 부족하면 [도입 절차](../../integrations/README.md)를 따른다.
- [테스트 기준](testing.md)과 필요한 [리뷰](review.md)를 적용한다.
