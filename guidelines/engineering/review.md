# 코드 리뷰

- 요구사항·범위·실제 diff·검증 근거를 함께 읽는다. 구현자의 요약만으로 판정하지 않는다.
- 정확성·요구 누락·회귀·보안·데이터 손실·유지보수 위험에 집중한다.
- 지적마다 위치·발생 조건·영향·근거를 남긴다. 확인된 결함, 확인 필요 사항, 선택적 제안을 구분한다.
- 취향·범위 밖 개선을 필수 수정으로 만들지 않는다. 중대한 판단 차이는 근거와 절충을 총괄에게 전달한다.
- 수정 후 해당 변경과 영향 범위를 재검토한다. 관련 없는 전체 리뷰를 매번 반복하지 않는다.
- 독립 리뷰는 위험·복잡도에 따라 적용한다. 에이전트 수가 품질을 보장한다고 가정하지 않는다.
- 검토자가 구현자의 결과를 자동 승인하거나, 반복 한도에 도달한 필수 결함을 완료로 처리하지 않는다.
