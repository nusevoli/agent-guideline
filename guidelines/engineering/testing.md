# 테스트와 검증

- 구현 구조를 그대로 따라가는 테스트보다 요구 행동·실패 위험·회귀를 검증한다.
- 프로젝트에서 필요한 검사 명령·환경·기대 결과를 확인한다. 위험에 따라 정상·경계·실패·통합 사례를 선택한다.
- 버그 수정은 가능하면 수정 전 재현 실패와 수정 후 성공을 확인한다. 어려우면 이유와 대체 근거를 기록한다.
- 작은 문서·표현 변경에 불필요한 테스트 코드를 만들지 않는다. 링크·내용·렌더링 등 변화에 맞는 검증을 한다.
- 린트 통과를 빌드·동작 검증 통과로 대체하지 않는다. UI·데이터·외부 연동은 필요한 실행 검증을 포함한다.
- 검증은 대상 커밋 또는 변경 상태, 환경, 명령/절차, 실제 결과, 미검증 범위를 [근거 양식](../../contracts/verification.md)에 기록한다.
- 새 변경·실패·모순이 없으면 같은 검사를 반복하지 않는다. 결과가 바뀔 수 있는 환경 의존성은 별도로 판단한다.
- AI가 수행할 수 있는 검사를 사용자에게 떠넘기지 않는다. 접근·판단이 필요한 부분만 요청한다.
- 테스트를 통과시키려고 승인된 요구나 검사 의미를 임의로 약화하지 않는다.
