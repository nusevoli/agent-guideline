# UX 검토

- 새 화면·핵심 사용자 흐름, 사용자 UX 불만, 정보 표현 방식 변경 시 적용한다.
- 먼저 프로젝트 목표·사용자 과제·사용 가능한 데이터를 확인한다. 시각적 선호와 과제 성공을 구분한다.
- 기존 화면의 문제를 근거로 기록하고 대안의 장단점·영향·추천 이유를 비교한다.
- 사용자 조사·UX 검토, 화면 설계, 구현 후 과제 검증 중 필요한 역할만 선택한다.
- 구체적인 스킬·에이전트 연결은 프로젝트에 두며 교체 가능하게 한다. 매번 모든 역할을 실행하지 않는다.
- 위임은 [위임 기준](../orchestration/delegation.md)을 따른다. 도구가 없으면 직접 검토임을 밝힌다.
- 대안 검토 → 방향 합의 → 구현 → 실제 조작 검증 순서로 진행하되 이미 합의한 범위를 재승인받지 않는다.
- 실제 관측한 관계만 시각화하고, 정상·오류·미검증·검사 대상 없음을 구분한다.
- 상세 근거 접근, 키보드 조작, 색상 외 상태 표현, 좁은 화면, 빈 결과·실패 상태를 고려한다.
- 완료 기준은 사용자가 수행할 과제로 정의하고 프로젝트 작업에 연결한다.
- 전문가 의견, AI 자기 검토, 실제 사용자 시험을 구분한다. 구현 완료나 전문가 추천만으로 사용성 향상을 주장하지 않는다.
- 작은 문구·간격 수정에는 전체 절차를 강제하지 않는다. 프로젝트 위험과 작업 규모에 맞춘다.
